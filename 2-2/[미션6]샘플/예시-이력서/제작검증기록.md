# 제작·검증 기록: 교육 운영 매니저 이력서

> 아래 AI 비교·테스트·수정·사용자 피드백은 작성 방법을 보여 주기 위한 가상 예시이며, 첨부 HTML을 실제로 검증한 기록은 아닙니다. 내 기록에는 실제로 쓴 AI와 직접 본 결과를 적습니다.

## 두 AI 비교

- AI A (서비스·모델 이름): 코디세이 플랫폼, 모델 A(회사 1)
- AI B (서비스·모델 이름): 코디세이 플랫폼, 모델 B(회사 2)
- 동일한 기획서와 함께 전달한 요청: “이 기획서.md대로 이력서를 만들어 줘. CSS와 JavaScript를 모두 HTML 파일 하나에 넣고, 다른 파일이나 로그인 없이 열리게 해 줘. 가상 인물의 정보를 쓰고, 화면 문구는 한국어로 해 줘. 기획서에 없는 기능은 넣지 마.”

| 테스트 내용 | AI A | AI B |
| --- | --- | --- |
| HTML 파일 열기 | 연락처와 경력·프로젝트가 구분돼 보임 | 경력마다 큰 카드가 생겨 두 곳의 경력을 한눈에 보기 어려움 |
| 이메일 복사 후 메모장에 붙여 넣기 | 화면과 같은 이메일 주소가 붙여 넣어짐 | 이메일 앱만 열리고 주소는 복사되지 않음 |
| 휴대폰으로 열기 | 한 줄로 배치가 바뀌어 가로로 밀지 않고 읽을 수 있음 | 2단 구성이 유지돼 본문 글자가 좁게 줄바꿈됨 |

- 선택한 결과물과 근거: A를 골랐습니다. 연락처와 경력을 구분해 읽을 수 있고, 이메일 복사와 휴대폰에서 읽기가 기획서대로 됐습니다. 인쇄했을 때 한 페이지에 들어가는지는 추가로 확인하기로 했습니다.

## 테스트 기록

| 번호 | 테스트 내용 | 예상 결과 | 실제 결과 |
| --- | --- | --- | --- |
| 1 | 파일을 열어 이름·경력·프로젝트 확인하기 | 김하린, 경력 두 곳, 프로젝트 두 개가 보임 | 빠진 항목 없이 보임 |
| 2 | ‘이메일 복사’를 누르고 메모장에 붙여 넣기 | harin.kim@example.com이 붙여 넣어짐 | 같은 주소가 붙여 넣어지고 복사 완료 안내가 나옴 |
| 3 (인쇄 조건으로 테스트) | 인쇄 미리보기에서 A4 세로·배율 100%로 보기 | 한 페이지에 들어가고 마지막 줄까지 보임 | 처음에는 두 페이지로 나뉨. 수정 기록 1로 고친 뒤 같은 설정에서 한 페이지에 들어감 |

## 수정 기록

### 수정 기록 1

- 발견한 문제: A4 세로·배율 100%로 인쇄 미리보기를 열었더니 한 페이지에 들어갈 줄 알았는데, 하단 내용이 두 번째 페이지로 넘어갔습니다.
- AI에게 전달한 요청: “인쇄 미리보기에서 A4 세로·배율 100%로 보면 하단 내용이 두 번째 페이지로 넘어가. 기존 2단 구성은 유지하고, 화면과 인쇄가 같은 A4 치수를 쓰도록 여백과 글자 크기를 맞춰 줘. 글자를 숨기거나 잘라서 맞추지는 마. 고친 HTML 전체를 다시 보여 줘.”
- 저장한 버전: `이력서_v1.html` → `이력서_v2.html`
- 수정 후 테스트 결과: 같은 인쇄 설정에서 한 페이지로 표시됐고 하단의 가상 예시 안내까지 보였습니다. 이메일 복사도 다시 해 보니 같은 주소가 붙여 넣어졌습니다.
- 수정 이유: 채용 담당자가 한 장으로 저장하거나 인쇄하려는데 일부 내용만 다음 페이지로 넘어가면 읽기 어렵습니다.

### 수정 기록 2

- 발견한 문제: 경력 요약과 담당 업무를 이어 읽어 보니 역할과 경험이 구분될 줄 알았는데, ‘준비하고 정리합니다’ 같은 설명이 반복돼 구체적으로 맡은 일이 잘 드러나지 않았습니다.
- AI에게 전달한 요청: “기획서에 적은 경력 자료만 사용해서 회사별 담당 업무를 짧은 항목으로 정리해 줘. 회사명·근무 기간·담당 업무는 구분하고, 제공하지 않은 수치나 성과는 만들어 넣지 마. 다른 기능은 유지하고 HTML 전체를 다시 보여 줘.”
- 저장한 버전: `이력서_v2.html` → `이력서_v3.html`
- 수정 후 테스트 결과: 회사별로 직무와 담당 업무를 구분해 읽을 수 있었고, 기간과 수치는 원래 자료와 같았습니다. 인쇄 미리보기에서도 한 페이지를 유지했습니다.
- 수정 이유: 경력을 읽는 사람이 표현을 해석하느라 시간을 쓰지 않고, 어떤 일을 맡았는지 바로 알 수 있어야 합니다.

### 수정 기록 3

- 발견한 문제: 동료에게 이력서를 PDF로 저장해 달라고 했습니다. ‘인쇄’ 버튼으로 저장할 줄 알았는데, 버튼을 보고 “프린터가 없는데 어떻게 해요?”라고 물으며 멈췄습니다.
- AI에게 전달한 요청: “동료가 ‘인쇄’ 버튼을 보고 프린터가 있어야 한다고 생각했어. 버튼 이름을 ‘인쇄 · PDF 저장’으로 바꿔 줘. 버튼을 누르면 인쇄 창이 열리는 동작과 다른 기능은 유지하고, 고친 HTML 전체를 다시 보여 줘.”
- 저장한 버전: `이력서_v3.html` → `이력서_v4.html`
- 수정 후 테스트 결과: 같은 동료에게 다시 PDF로 저장해 달라고 하니 ‘인쇄 · PDF 저장’을 눌러 인쇄 창에서 PDF 저장을 선택했습니다. 저장한 파일은 한 페이지였고, 이메일 복사도 이전처럼 됐습니다.
- 수정 이유: ‘인쇄’라고만 적혀 있으면 프린터 없이 파일로 저장할 수 있다는 것을 모를 수 있습니다.

마지막 버전을 `이력서.html`로 정리해 제출합니다.

## 사용자 테스트

- 테스트 참여자와 요청한 작업: 동료에게 사용법을 설명하지 않고 “이 이력서를 PDF로 저장해 줘”라고 부탁했습니다.
- 사용자의 행동과 질문:
  - 화면 위의 ‘인쇄’ 버튼을 읽었지만 누르지 않았습니다.
  - “프린터가 없는데 어떻게 해요?”라고 물었습니다.
- 받은 피드백: “이 버튼으로 PDF도 저장할 수 있는 줄 몰랐어요. 버튼에 같이 적혀 있으면 좋겠어요.”
- 반영 내용과 결과: 수정 기록 3처럼 버튼 이름을 ‘인쇄 · PDF 저장’으로 바꾸고 기획서에도 같은 이름을 적었습니다. 다시 부탁하니 버튼을 눌러 PDF로 저장했습니다.
