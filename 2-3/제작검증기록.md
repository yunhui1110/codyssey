# 제작·검증 기록: 눈사람 눈송이 받기

## 두 AI 비교

- AI A (서비스·모델 이름): ChatGPT
- AI B (서비스·모델 이름): Claude Code
- 동일한 기획서와 함께 전달한 요청: “이 기획서.md대로 HTML 파일 하나를 만들어 줘. CSS와 JavaScript까지 모두 이 파일 하나에 넣고, 다른 파일이나 로그인 없이 브라우저에서 바로 열리게 해 줘. 화면 문구는 한국어로 쓰고, 기획서에 없는 기능은 넣지 마”

| 테스트 내용 | AI A | AI B |
| --- | --- | --- |
| 파일을 열어 화면 디자인 보기 | 폰트가 안예쁨 | 디자인이 보기 좋았음 |
| 떨어지는 눈송이 모양 보기 | 눈송이가 그냥 동그란 구형태 | 눈송이가 내가 원하는 모양으로 잘 구현됨 |
| 브라우저 창의 폭을 좁게 조절하기 | 폭을 줄이면 오른쪽 화면이 다 짤렸다 | 잘리지 않고 글자가 다 보임 |

- 선택한 결과물과 근거: B(Claude Code)를 골랐습니다. 디자인이 보기 좋았고, 눈송이도 내가 원하는 모양으로 잘 구현된 것 같아서 선택했습니다. 화면의 폭을 조절해도 잘리지 않고 글자가 다 보였습니다.
- 선택한 파일: `눈사람_눈송이받기 v1.html` (AI B 결과물)

| 버전 | 바꾼 내용 | 구분 |
| --- | --- | --- |
| v1 | 이전 미션에서 고른 AI B 결과물 | - |

| v3 | 눈송이 나오는 간격(0.5~1.5초)과 떨어지는 속도(0.8~1.2배)를 무작위로 | 수정 기록 1 |
| v4 | 남은 시간이 줄수록 눈송이가 빨라져 끝 무렵 약 2배 | 기획 변경 |

- v2와 v4는 테스트에서 발견한 문제가 아니라 내가 바꾸고 싶었던 기획 변경이라, 수정 기록 3건에는 넣지 않고 여기에만 적었습니다.
- v2를 만들 때 시작 화면의 흐림 효과에 ‘남은 시간 45초’와 ‘받은 눈송이 0개’가 가려져 흐리게 보여서, 기획서대로 위쪽 글자가 또렷하게 보이도록 함께 고쳤습니다.

## 수정 기록

### 수정 기록 1 (v2 → v3)
- 발견한 문제: 한 판을 지켜보니(테스트 내용) 눈송이가 예측하기 어렵게 떨어질 줄 알았는데(예상 결과) 눈송이가 너무 일정한 간격과 속도로 떨어졌습니다(실제 결과).
- AI에게 전달한 요청: “눈 송이가 너무 일정하게 떨어지는데 랜덤하게 떨어지도록 해.” (기획서에 ‘나오는 간격은 0.5초에서 1.5초 사이에서 매번 무작위, 눈송이마다 떨어지는 속도가 조금씩 다름’을 먼저 적은 뒤, 그 기획서대로 이 부분만 고쳐 달라고 요청)
- 수정 후 테스트 결과:
  - AI 자동 테스트: 한 판에 눈송이 43개가 나왔고, 간격은 0.52초~1.50초 사이로 섞여 평균 1.03초였습니다. 끝 화면 개수와 위쪽 개수가 같았고(6개), ‘다시 하기’를 누르면 45초·0개로 돌아갔습니다.
  - 직접 확인: (직접 해 보고 본 것을 적기. 예: 두 개가 붙어서 나올 때도, 한참 안 나올 때도 있었는지)
- 수정 이유: 눈송이가 같은 박자로 떨어지면 몇 번 하면 리듬이 외워져 한 판이 지루해지고, 기다리는 시간을 보내려는 목적에 맞지 않습니다.

### 수정 기록 2 (v4 → v5)
- 발견한 문제: 남은 시간이 얼마 안 남아 눈송이가 빨라졌을 때, 눈사람이 한쪽 끝에 있고 눈송이가 반대쪽 끝에서 나오는 상황에서 방향키를 계속 누르고 있어 보니(테스트 내용) 눈송이를 받을 수 있을 줄 알았는데(예상 결과) 눈사람이 도착하기 전에 눈송이가 바닥에 떨어졌습니다(실제 결과).
- AI에게 전달한 요청: “눈사람 이동속도가 너무 느려서 눈송이가 빠르게 내려오면 양 끝에 눈은 물리적으로 받을 수 없게되었다. 이 부분을 수정해줘. 수정할때 기존에 기획했던 다른 부분들을 임의로 수정하거나 바꾸지마”
- 수정 후 테스트 결과:
  - AI 자동 테스트: 남은 시간 약 4초, 가장 빠른 눈송이가 오른쪽 끝, 눈사람이 왼쪽 끝인 상황을 화면 크기 5가지(1000×700, 1920×1000, 1280×500, 375×640, 2560×600)에서 해 보니, v4는 375×640에서만 받았고 v5는 5가지 모두에서 받았습니다. 시작 전 45초 유지, 끝 화면 개수 일치, 끝난 뒤 키 무반응, ‘다시 하기’도 이전과 같았습니다.
  - 직접 확인: v5를 직접 구동해 보니 눈사람 속도가 아직 개선되지 않은 것처럼 느껴졌습니다. → 수정 기록 3
- 수정 이유: 끝 무렵에는 아무리 빨리 움직여도 받을 수 없는 눈송이가 생기면, 실력과 상관없이 점수가 깎이고 사용자는 게임이 불공평하다고 느낍니다.
- 기획서 반영: ‘화면 구성과 동작’에 ‘눈사람은 화면 반대쪽 끝에서 나온 가장 빠른 눈송이도 받을 수 있는 속도로 움직입니다’를, ‘완료 기준’에 같은 상황의 테스트를 더했습니다.

### 수정 기록 3 (v5 → v6)
- 발견한 문제: 수정 기록 2를 고친 v5를 직접 구동해 보니(테스트 내용) 눈사람이 v4보다 눈에 띄게 빨라질 줄 알았는데(예상 결과) 눈사람 속도가 아직 개선되지 않은 것처럼 느껴졌습니다(실제 결과).
- AI에게 전달한 요청: “구동 해봤는데 눈사람 속도가 아직 개선되지 않은것같아 눈사람 속도를 빠르게 이동할 수 있도록 수정해.”
- AI가 확인한 내용: v5는 화면 크기에 맞춰 속도를 계산하는데, 폭이 800px보다 좁거나 세로로 긴 창에서는 계산값이 최솟값(1초에 360px)보다 작아 v4와 같은 속도가 쓰였습니다. (예: 400×700, 600×800 창에서 360)
- 수정 후 테스트 결과:
  - AI 자동 테스트: 최솟값을 720으로 올리자 400×700·600×800·800×900 창에서 720, 1000×700에서 931, 1920×1080에서 1121이 되었습니다. 수정 기록 2의 양 끝 테스트를 5가지 화면에서 다시 해 보니 모두 받았고, 눈사람은 화면 밖으로 나가지 않았습니다. 시작 전 45초 유지, 끝 화면 개수 일치(12개), 끝난 뒤 키 무반응, ‘다시 하기’도 이전과 같았습니다.
  - 직접 확인: v6을 구동해 보니 눈사람이 빠르게 움직여 만족스러웠습니다. (양 끝 눈송이를 받아 봤는지 등 직접 본 것을 더 적기)
- 수정 이유: 창 크기에 따라 눈사람이 여전히 느리면, 수정 기록 2를 고쳤어도 그 창에서는 끝 무렵 양 끝 눈송이를 받기 어렵고 조작이 답답합니다.
